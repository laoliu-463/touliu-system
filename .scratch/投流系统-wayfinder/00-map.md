## Decisions so far

> 每条以"标题：摘要"列出，按问到的先后。决策原文也在烧烤中已留底，本节只作索引。

1. **验收标准**：迁完上 SmartAdmin，同一域名，能看真实商家数据（11 个千川账户真实消耗完整可读）。
2. **四五期范围**：第四期第五期 out of scope。注：4-5 的 4 角色 RBAC 临时前置到前 3 期以满足多租户隔离。
3. **燃星 Python 处理**：冻结为只读真理源，不再接新需求。`燃星-千川系统/` 仍可读但不写代码。
4. **技术栈**：SmartAdmin（Java 17 + Spring Boot 3 + TS + Ant Design Vue），底座已在 `qianchuan-mvp-smartadmin/`。
5. **业绩算法节奏**：第二期其他部分（账户表、计划表、商品表、素材表、计划日报表、合作方式标记、排行榜非算法部分、授权快到期提醒）先做完；算法（分佣/代投/退款/结算率/保本 ROI）最后一步填 NULL 列，等业绩算法 ADR 决策票产出后再统一填。
6. **第三期自动程度**：先只告警，人点头后再执行。
7. **多租户隔离**：RBAC 四角色（管理员/运营/商务/剪辑）× 三数据范围（本人/本部门/全公司），精到接口级。
8. **告警通道**：飞书 webhook（用户已习惯）+ 站内收件箱（详情回看、改已读、确认操作）。
9. **文件存储**：腾讯云 COS（第四期 4-3 用，本期不进票）。
10. **监控默认开关**：默认全关，人手动开（隐含「先只告警」决策）。
11. **第九章其余**：「保本 ROI」随业绩算法处理；「达人接表」「直接新建计划」out of scope。
12. **11 账户 token 处置**：用现有 refresh_token 沿用；迁完时所有 token 必须在剩余 ≥7 天有效期内，否则触发续授权提示；剩余不足 1 小时时自动用 refresh_token 换发。
13. **RBAC 角色清单**：4 个角色 × 3 数据范围。完整 RBAC（部门树、菜单权限、接口注解）仍归第四期，本期只保证「谁可访问、可见范围」。
14. **监控频率**：全局 3 分钟 × 账户数 × 监控项数；用 Spring Scheduler + Sa-Token + 单点；按需做批量合并。
15. **告警 UI**：推送（飞书 webhook 富文本卡片）+ 站内收件箱（数据库持久化 + SmartAdmin 列表 + 详情页）。
16. **[业绩算法口径](qianchuan-mvp-smartadmin/docs/adr/0001-业绩算法.md)**：佣金率人工录入；退款整笔扣；结算率 × 1 进业绩；代投按消耗提成；保本 ROI = 1 ÷ 毛利率；重算历史走手工按钮接口 `/api/v1/performance/recompute`。
17. **[token 看门狗设计](qianchuan-mvp-smartadmin/docs/adr/0002-token看门狗.md)**：全 MySQL 不引 Redis；status 4 值 + phase 实时算；3 分钟同 cron；重试 3 次退避；商家 1 天 + 6 小时两段提示；心跳表自检；主表 + `token_history` 归档；账户表加 `last_synced_at`。
